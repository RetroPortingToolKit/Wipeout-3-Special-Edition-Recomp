# Clean AOT executable-region catalog

This directory contains the first clean-AOT boundary for executable-region
identity and selection. It is intentionally self-contained and uses only the
Python standard library. It does not import, invoke, or reproduce a runtime
compiler, an executable capture pipeline, or an interpreter.

## Identity model

An executable variant is identified by the exact tuple:

```text
load_range + sha256 + relocation_metadata
```

`load_range` is a half-open, 32-bit guest-address range. The SHA-256 is the
hash of the bytes in that range before relocation. Relocation metadata is an
optional canonical JSON object; `null` and an object are different identities.
The catalog permits multiple content epochs at the same address, provided
their hashes or relocation metadata differ. A selector never treats a missing
variant as a request to compile or interpret the bytes.

A selection request's digest is not trusted on its own. Selection succeeds
only after the implementation stream-hashes the supplied executable file (or
hashes the supplied in-memory bytes), verifies its exact range length, and
matches the complete identity tuple. This makes a claimed digest, partial
image, relocated near-match, or same-address unknown epoch a rejection.

Every variant also records:

- 4-byte-aligned dispatch roots;
- sorted, coalesced executed ranges;
- explicit branch/delay-slot ownership, including page-crossing slots;
- source-media file names, sizes, and hashes (no media bytes);
- the relative path, ID, and SHA-256 of the already-built native artifact.

Artifact paths are NFC-normalized relative POSIX paths with additional
portable-filesystem restrictions. Absolute, drive-relative, UNC, traversal,
Windows device, case-fold-colliding, trailing-dot/space, formatting-control,
and non-NFC paths are rejected. Before returning a selection, the artifact is
resolved beneath the configured root without symlinks or junctions and its
bytes are checked against the manifest SHA-256.

The manifest-wide stack window is a forbidden range. Load ranges, roots,
executed ranges, and delay-slot ownership may not overlap it. Roots must be
inside an executed range. Executable ranges and instruction ownership are
4-byte aligned and cannot cross the address-space limit.

## Canonical JSON

The package defines a narrow canonical JSON profile: objects have string keys,
keys are sorted lexicographically, arrays retain their declared order, numbers
are integers only, non-ASCII is emitted as UTF-8, and separators contain no
whitespace. Duplicate object keys, floats, NaN, Infinity, invalid Unicode
scalars, and integers outside the interoperable JSON range are rejected.
SHA-256 digests are computed over these canonical UTF-8 bytes without a final
newline. CLI JSON output adds one newline for terminal use.

## CLI

Run from this directory, or set `PYTHONPATH` to it:

```powershell
python -m psx_catalog validate manifest.json
python -m psx_catalog normalize manifest.json
python -m psx_catalog hash precompiled/region-a.bin
python -m psx_catalog select manifest.json request.json executable.bin artifact-root
```

`select` exits `0` only when both the executable and native artifact bytes have
been measured and an exact precompiled variant is selected. Unknown code,
byte/range mismatches, missing artifacts, indirect artifact paths, and native
integrity failures print a compact canonical rejection receipt and exit `3`.
Malformed manifests, requests, paths, or command lines print a canonical
validation error and exit `2`. There is no fallback selection result.

The request file has the same identity fields used by a variant:

```json
{
  "load_range": {"start": 4096, "end_exclusive": 4352},
  "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "relocation_metadata": null
}
```

The exact manifest schema and validation details are encoded in
`psx_catalog.model`; keeping the parser strict is deliberate so a future
runtime cannot silently accept an unreviewed field.

## Executable authorization evidence

`evidence/executable-authorization.json` is the current fail-closed analysis
receipt for the authenticated main executable and the route-observed NFE entry
5 variant. It is deliberately not a selectable catalog manifest: unresolved
indirect transfers and rejected direct edges remain, and no native artifacts
exist for these partial regions. The receipt records exact authorized and
unknown ranges, direct-edge closure failures, finite indirect targets,
unresolved indirect sites, and delay-slot ownership. It is generated by
`tools/analysis/authorize_executable_regions.py`, which verifies all input
hashes and uses Ghidra/capture evidence only as cross-evidence; neither source
can independently authorize a root or executable byte.

`main-exe-finite-indirect-targets.json` is a smaller identity-bound manifest
for finite static target proofs. Its first closed site is the authenticated
masked-offset dispatch at `0x8016FC74`: the exact instruction bytes prove all
eight possible aligned targets without assigning a target to any unresolved
callback, return-value, or memory-loaded transfer. The deterministic generator
rejects wrong image identities, instruction near-matches, unbounded masks, and
unsorted or duplicate site declarations. The manifest also records the exact
zero-trip initializer loop at `0x80162564`: its authenticated link-time count is
zero and its branch skips the table call, so the only honest finite target set
for that unreachable `jalr` is empty. Near-matches in the count, skip branch,
or loop backedge fail closed.

`evidence/content-static-coverage.json` is the deterministic media-to-static
coverage audit. The current tranche catalogs the main executable plus every
expanded NFE/PBP payload (5,179 records), binds the two authenticated executable
identities, reconciles the two supplemental finite main-image sites, and maps
four observed NFE runtime epochs. It deliberately remains
`incomplete-fail-closed`: exact bounded TIM and Sony VAG parsing proves 106
payloads are data, while 5,071 payloads still lack an authenticated code/data
role. Of those, 1,722 have a fully validated 16-byte Wip3out name envelope and
a separately hashed unknown-role body; 3,349 remain opaque. Exact content
deduplication reduces that review frontier to 650 unique payload identities
without using duplication as evidence that any identity is data. The strict raw
MIPS ABI-shape scan finds no additional candidate beyond the already-bound NFE
entry 5, but unknown executable risk remains open rather than treating that scan
as proof of absence. In addition,
106 indirect sites remain after 46 exact literal A0/B0/C0 vector exits were
closed without admitting any computed callback. Six overlapping-address edges
are now governed by the authenticated epoch-discriminator contract rather than
remaining rejected. The direct
corridor recovery receipt authenticates 1,107 newly admitted instructions in
22 exact hashed ranges; no unresolved indirect was relaxed. The 13 ISO audio pseudo-files
outside the data-track image are explicitly excluded rather than silently
treated as payloads.

`evidence/content-payload-clusters.json` is the identity-level extension,
exact-size, leading-magic, occurrence-frequency, and structure clustering
receipt for all 650 unknown-role hashes. It binds the complete content audit,
records every identity exactly once, and identifies the dominant numeric and
named-envelope families without assigning semantic roles from a cluster label.
Named bodies are recursively hashed and checked for complete TIM/VAG children,
embedded bounded PS-X EXE containers, and raw MIPS ABI candidates. A parser miss
does not close executable risk.

`evidence/generated-game-shards.json` is the first non-zero generated game-code
coverage receipt. It currently admits 83,244 instructions in 583 regions.
`tools/analysis/build_game_region_shards.py` derives it from
the executable authorization and finite-target evidence as a greatest closed
set. Sources of rejected or unresolved edges, their reverse direct closure, and
non-atomic delay slots are excluded. The paired `*-closed-shards.manifest`
files enumerate every admitted instruction as an explicit compiler entry;
unknown identities and PCs remain runtime rejections. This receipt deliberately
claims partial coverage, not whole-game closure.
