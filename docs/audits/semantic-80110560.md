# Semantic audit: `0x80110560`

## Result

`0x80110560` is `DrawSignedDecimalInteger`, a compact decimal layout owner.
It emits an optional minus glyph, converts a signed value to decimal digits,
applies caller-requested leading-zero padding, and threads the X pen through
`EmitFontGlyphPacket`.

## Exact boundary and ABI

The function allocates a `0x58`-byte frame at `0x80110560`, saves `ra` and
`s0`--`s3`, and uses `sp+0x10` onward as a local digit array.  Its single
epilogue begins at `0x801106B0`; `jr ra` is at `0x801106C8` and the delay slot
restores `sp` at `0x801106CC`.  The exact half-open interval is therefore
`[0x80110560,0x801106D0)`, `0x170` bytes, matching the generated range.

The recovered ABI is:

```c
int DrawSignedDecimalInteger(
    int32_t value, int x, int y, int style, int minimum_digits);
```

The fifth argument is loaded from incoming stack `+0x10` (new-frame `+0x68`).
`a2`/`a3` are preserved as Y/style.  The routine returns the final X pen from
the final glyph call; the zero value always produces at least one digit.

## Decimal and padding behavior

For a negative input, the routine applies `negu`, emits glyph `0x28` at the
current X, and begins the magnitude there.  It then repeatedly performs signed
division by ten using the exact `0x66666667` reciprocal sequence, stores each
remainder, and stops when the quotient becomes zero or five digits have been
collected.  Digits are emitted most-significant first as glyph `0x1A + digit`.

If conversion ends before `minimum_digits`, zero remainders are appended so
the reverse emission produces leading zeroes.  Authored callers pass widths
zero or two.  The implementation has no local validation that a larger width
fits the five-word scratch array, so `0..5` is the safe caller contract.  Values
with more than five decimal digits are deliberately truncated to their low
five digits.  `INT32_MIN` also cannot be represented by the signed `negu`
magnitude path and is outside the normal authored domain.

## Style and render effects

Before any emission, word `0x8018AE94` is compared with 2.  When equal and the
caller's style is below 6, the style is increased by 14.  Otherwise it is used
unchanged.  This is the same low-to-high font-style-bank remap used by the
nearby numeric formatter.

The only callee is confirmed `EmitFontGlyphPacket` (`0x80105CDC`), at one
minus-sign site and one digit-loop site:

```c
x = EmitFontGlyphPacket(glyph, x, y, remapped_style);
```

Consequently this owner has no direct global mutation beyond the callee's
confirmed `POLY_FT4` allocation/ordering-table effects.  Its own state is the
single mode-word read plus private stack digits.

## Exhaustive direct callers and interior targets

An aligned scan of the loaded EXE finds exactly ten direct JAL sites:

```text
800FE264 800FEA84 800FEB98 800FED68 800FEDD0
80102450 8010256C 80126F28 80127020 801272D4
```

Grouped by owner:

- `0x800FE194`: `0x800FE264`
- `0x800FE978`: `0x800FEA84`, `0x800FEB98`, `0x800FED68`, `0x800FEDD0`
- `0x80102384`: `0x80102450`
- `0x801024C8`: `0x8010256C`
- `0x80126E94`: `0x80126F28`, `0x80127020`
- `0x8012714C`: `0x801272D4`

Five sites pass `minimum_digits = 2`, three pass zero, and the paired sites at
`0x800FED68`/`0x800FEDD0` pass the owner's saved `s7` value.  No J or JAL from
outside the owner targets an interior instruction.
