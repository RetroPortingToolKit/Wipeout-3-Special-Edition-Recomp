# Semantic audit: `0x80168080`

## Result

`0x80168080` is the confirmed CD-ROM command core `IssueCdCommand`, not an SIO
exchange. The proof is direct: its four retained register pointers at
`0x8017B3E8..0x8017B3F4` contain `0x1F801800`, `0x1F801801`, `0x1F801802`, and
`0x1F801803`, the PSX CD-ROM indexed register block; its timeout diagnostics
begin with the retained string `CD timeout: `; and command 2/14 handling matches
Setloc/Setmode parameter caching.

Its recovered ABI is:

```c
int IssueCdCommand(
    uint8_t command,
    const uint8_t *parameters,
    uint8_t *sync_response,
    int asynchronous);
```

It returns zero when a command is accepted/completes successfully, `-1` for a
synchronous timeout or CD DiskError phase, and `-2` when a command that requires
parameters is issued with a null parameter pointer.

## Exact boundary and callers

The function opens a 56-byte frame at `0x80168088`, after its first diagnostic
level load, saves `ra` and `s0..s6`, and joins all exits at `0x80168464`. It
returns at `0x80168484` with stack restoration at `0x80168488`. The next
independent CD helper begins at `0x8016848C`. Thus the exact interval is
`[0x80168080,0x8016848C)`, or `0x40C` bytes, matching the generated range.

An aligned JAL scan finds exactly 13 direct calls:

```text
80160FB0 80160FD8 80160FFC 801610E4 8016110C 80161130 80161218
80161240 80161264 8016881C 80168844 80168858 80168874
```

The `0x80160Fxx..0x801612xx` sites belong to synchronous/asynchronous CD
control wrappers; `0x801688xx` uses commands 1, 10, and 12 during CD setup.
Only `0x80161130` passes `asynchronous=1`; the other visible calls wait
synchronously.

## CD register protocol

The register pointer words prove these byte accesses:

| Pointer word | MMIO value | Role used here |
|---:|---:|---|
| `0x8017B3E8` | `0x1F801800` | CD index/status register |
| `0x8017B3EC` | `0x1F801801` | command register write |
| `0x8017B3F0` | `0x1F801802` | parameter FIFO write |
| `0x8017B3F4` | `0x1F801803` | IRQ flag/mask bank access by helpers |

The low command byte indexes a word table at `0x8017B368`. Its positive value
is the exact parameter byte count. If that count is nonzero and `parameters`
is null, the function optionally prints a diagnostic and returns `-2` without
issuing the command. Otherwise it writes precisely that many bytes in order to
the parameter FIFO at `0x1F801802`, then writes the command byte to
`0x1F801801`.

Before issue it clears two phase bytes at `0x8017B400/+1` and clears the byte
through the `0x1F801800` pointer. A command-indexed phase table at `0x8017B268`
causes the second phase byte to be cleared for commands that expect a ready
phase. The current command is also saved at `0x8017B141`.

Two command-specific caches corroborate standard CD command identities:

- command `0x02` copies its first four Setloc parameter bytes to
  `0x8017B13C..0x8017B13F`;
- command `0x0E` copies its first Setmode byte to `0x8017B140`.

The function calls `0x80167B38(0,0)` before staging these fields, providing the
shared CD phase/reset preparation used by the higher retry wrapper.

## Asynchronous and synchronous paths

When `asynchronous != 0`, the function returns zero immediately after writing
parameters and command. It does not copy a response and does not wait for an
IRQ phase; completion is owned by the installed CD callbacks.

The synchronous path establishes two independent watchdogs:

- VBlank deadline `VSync(-1) + 0x3C0` (960 software VBlanks);
- a tight-loop counter that times out once the previous count is greater than
  `0x003C0000`.

It polls sync-phase byte `0x8017B400`. While zero, it repeatedly calls
`VSync(-1)` and checks both watchdogs. It also enters the installed critical
section/IRQ service path through `0x80162680`; when active, it saves the low two
CD index bits, repeatedly calls `0x801675D4` until no CD phase flags remain,
dispatches the ready callback at `0x8017B128` for returned bit 2^2 and the sync
callback at `0x8017B124` for bit 2^1, then restores the saved index bits.

The callback arguments are the corresponding phase byte and internal response
buffer:

| Phase | State byte | Callback | Eight-byte buffer |
|---|---:|---:|---:|
| sync | `0x8017B400` | `0x8017B124` | `0x801EEB20` |
| ready | `0x8017B401` | `0x8017B128` | `0x801EEB28` |

The retry wrapper temporarily clears/restores the sync callback word, which is
why the earlier audit saw callback suppression around this lower command core.

## Completion, response, and errors

Once sync phase becomes nonzero, a nonnull caller response pointer receives
exactly eight bytes copied from `0x801EEB20`, irrespective of the command's
shorter logical response length. Phase value 5, the CD DiskError interrupt
reason, maps to return `-1`; every other nonzero completed sync phase returns
zero.

If either watchdog expires, the function prints `CD timeout: ` followed by the
formatted command name and current sync/ready phase names using retained
tables, calls recovery helper `0x80168514`, and returns `-1`. It does not retry
internally. Retry policy—up to four attempts and final recovery
classification—belongs to the higher `CdControlWithRetry` wrapper.

No path returns partial response length. The caller's output buffer is left
untouched on asynchronous issue, missing-parameter rejection, and timeout; on
a completed DiskError phase it still receives the eight-byte sync response
before `-1` is returned.

## Corrected subsystem identity

The prior `0x8016118C` audit and catalog called this an SIO exchange. That was
incorrect: SIO0 is at `0x1F801040`, SIO1 at `0x1F801050`, while every register
pointer here targets CD-ROM `0x1F801800..03`. This audit renames the upper owner
`CdControlWithRetry` and updates its documentation. The recovered retry,
preflight, and callback-suppression mechanics remain valid; only their device
identity and buffer terminology changed.
