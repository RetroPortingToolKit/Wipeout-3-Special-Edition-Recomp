# Semantic audit: `0x80161058`

## Result

`0x80161058` is the PsyQ asynchronous CD-ROM command adapter `CdControlF`.
It shares `CdControl`'s recovery/preflight sequencing but submits the requested
command with the asynchronous flag and accepts no result buffer.

## Boundary, ABI, and return

The function allocates a `0x38`-byte frame at `0x80161058`, saves `ra`, `fp`,
and `s0`--`s7`, and uses one common epilogue.  `jr ra` is at `0x80161184`; the
delay slot restores `sp` at `0x80161188`.  The next independent owner begins at
`0x8016118C`, proving `[0x80161058,0x8016118C)`, `0x134` bytes.

The recovered ABI is:

```c
int CdControlF(uint32_t command, const void *parameters);
```

Only `command & 0xFF` is retained.  `a2` and `a3` are unused.  A requested
command accepted by `IssueCdCommand` (lower result zero) returns 1; four
immediate failures return 0.  This reports submission acceptance, not eventual
asynchronous command completion.

## Recovery, preflight, and async submission

The sole callee is confirmed `IssueCdCommand` (`0x80168080`).  Each attempt can
perform this sequence:

1. Unless the requested command is 1, if status byte `0x8017B130` has bit
   `0x10`, issue synchronous `(1, NULL, NULL, 0)` recovery.  Its result is
   intentionally ignored.
2. If `parameters != NULL` and command-table word
   `0x801792D8[command & 0xFF]` is nonzero, issue synchronous
   `(2, parameters, NULL, 0)` preflight.  A nonzero immediate result retries.
3. Restore the callback and submit
   `(command & 0xFF, parameters, NULL, 1)`.

The final `a3 = 1` is the material distinction from synchronous `CdControl`.
The independently audited command core uses that flag to return after command
submission rather than service all completion IRQ phases.  No response buffer
is supplied on any `CdControlF` call.

The retry counter starts at 3 and decrements after preflight or requested-submit
failure until it reaches `-1`, allowing at most four attempts.  It cannot retry
a later asynchronous completion failure because this owner has already
returned.

## Callback and hardware ownership

The word at `0x8017B124` is saved at entry and zeroed at the beginning of each
attempt, suppressing the installed CD sync callback during synchronous recovery
and preflight.  It is restored immediately before the asynchronous requested
submission and after final exhaustion, so every exit preserves prior callback
state.

This wrapper performs no direct MMIO.  `IssueCdCommand` owns writes to the
CD-ROM parameter/command registers at `0x1F801802/0x1F801801`, immediate IRQ
protocol setup, and any synchronous watchdog handling.  `CdControlF` owns only
sequence selection, callback isolation, bounded immediate retry, and boolean
normalization.

```text

```

Grouped by owner:

- `0x8011364C`: one call;
- `0x80160548`: one call;
- `0x801607BC`: one call;
- `0x8016088C`: two calls.

No external J or JAL targets an interior instruction.  The adjacent
`CdControlWithRetry` at `0x8016118C` is an independent framed owner, not a tail
or alias of this routine.
