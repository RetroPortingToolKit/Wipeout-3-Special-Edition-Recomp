# Semantic audit: `0x80121534`

## Result

`0x80121534` is the confirmed 704-byte shared audio sink named
`AllocateAndQueueSoundVoice`. It accepts a resource handle plus volume, pan,
pitch, pitch-scale, class/flags, and optional fixed-voice selector; allocates a
sound-instance slot and one or two voices; initializes their software/SPU
state; and submits the instance to the selected audio backend.

Its recovered call shape is:

```c
void AllocateAndQueueSoundVoice(
    int resource,
    uint8_t volume,
    uint8_t pan,
    uint8_t pitch,
    int pitch_scale_q8,
    uint32_t class_flags,
    int16_t fixed_voice);
```

No path establishes a meaningful return value.

## Exact boundary

The function opens a unique 56-byte frame at `0x80121534`, saves `ra`, `fp`,
and `s0..s7`, and every success or rejection path joins the restores at
`0x801217C4`. It returns at `0x801217EC`, with the stack restore in the delay
slot at `0x801217F0`. A different function opens its own 56-byte frame at
`0x801217F4`. Therefore the exact interval is
`[0x80121534,0x801217F4)`, or `0x2C0` bytes, matching the generated range.

## Admission and sound-instance allocation

The sink returns immediately unless both global audio-enable bytes
`0x80175E68` and `0x80175E6D` are nonzero. It calls `0x801225F8`, whose exact
scan selects the first inactive entry among 24 records rooted at `0x801D674C`,
with a stride of `0x20`; `-1` means the pool is full and is another no-op.

For allocated sound-slot index `s`, it initializes:

| Slot field | Value |
|---:|---|
| `+0x00` | `900` |
| `+0x04` | resource descriptor word `+0x10` |
| `+0x08` | active state `1` |
| `+0x0C` | incoming `class_flags` |
| `+0x10` | incoming Q8 pitch scale |
| `+0x18` | primary voice index |
| `+0x19` | secondary voice index, or `-1` |
| `+0x1A` | low byte of volume |
| `+0x1B` | low byte of pan |
| `+0x1C` | low byte of pitch |

The resource argument is an integer handle, not the final sample pointer. It
indexes 20-byte descriptors at `0x801D59EC + resource*0x14`. This corrects the
looser “resource pointer” wording used by the two upstream wrapper audits.

## Voice selection and state effects

There are 24 36-byte voice-state records at `0x801D63EC`. Any fixed selector
of 21 or greater is used directly without a bounds check; all retained callers
restrict that path to 21, 22, or 23, the three valid reserved voices. This is
how sound-effect IDs 28, 37, and 29 receive dedicated voices. Any selector
below 21 is passed to `0x80121F3C`, which searches the 21 ordinary voices and
returns a voice index or `-1`.

For primary voice `v`, the sink writes these fields in the 36-byte state:

| Voice field | Value/effect |
|---:|---|
| `+0x00` | preserve existing word, OR control bits `0x90` |
| `+0x04` | resource descriptor word `+0x00` |
| `+0x08` | `1` |
| `+0x0C` | normally `1`; changed to `2` when a second voice is requested |
| `+0x18` | signed `(pitch_scale_q8 * descriptor[+0x10]) / 256` |
| `+0x1C` | owning sound-slot index |

Signed division by 256 is implemented by adding 255 to negative products
before the arithmetic shift, so it truncates toward zero. If `class_flags`
has bit `0x10`, bit 31 is also set in the primary voice's `+0x00` control word.

If `class_flags & 8`, the primary voice's `+0x0C` becomes `2` and the sink
allocates a second ordinary voice. On success it records that index at sound
slot `+0x19` and initializes the same resource pointer, pitch scalar, owner,
active words, and `0x90` control bits. On failure, `+0x19` remains `-1`. Without
bit 8, no second allocation is attempted and `+0x19` is explicitly `-1`.

Finally `0x8012257C(sound_slot)` dispatches the populated state to one of two
lower audio update routines according to backend-mode byte `0x801D6E55`
(mode 1 calls `0x80121C6C`, mode 2 calls `0x80121D4C`). The sink itself does
not directly write SPU registers; it builds the authoritative queued state and
hands it to that backend dispatcher.

## Callers and upstream meaning

An exact aligned opcode scan of the main executable finds only three direct
calls:

```text
0x80136F2C  PlaySpatialSoundAtSegmentMidpoint
0x80137E88  PlaySoundEffectById, dedicated resource/class-18 path
0x80137EC0  PlaySoundEffectById, ordinary resource/class-2 path
```

The spatial wrapper passes resource-table entry `0x801E178C[id]`, derived
volume and pan, pitch byte 15, Q8 pitch scale `control+0x100`, class zero, and
dynamic selector zero. The generic wrapper passes its selected resource
handle, truncated volume/pan/pitch bytes, caller pitch scale (commonly 256),
class 2 or 18, and selector 0 except for the dedicated 21..23 mappings. These
call shapes, together with the descriptor and voice writes, prove the ABI and
the volume/pan/pitch interpretation.
