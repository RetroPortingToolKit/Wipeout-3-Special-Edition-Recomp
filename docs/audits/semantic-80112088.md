# Semantic audit: `0x80112088`

## Result

`0x80112088` is the logical packed-record converter
`SwapPackedRecordU16FieldsByType`. It selects one pair of two-byte fields from
the record's type byte and exchanges the two fields without changing byte
order inside either field.

Its recovered ABI is:

```c
void SwapPackedRecordU16FieldsByType(uint8_t **record_slot);
```

More exactly:

```c
uint8_t *record = *record_slot;
if (record[0] == 2) {
    swap(record[8],  record[12]);
    swap(record[9],  record[13]);
} else if (record[0] == 6) {
    swap(record[4],  record[8]);
    swap(record[5],  record[9]);
}
```

There is no semantic return value.

## Logical boundary and generated splits

The entry range is generated as `[0x80112088,0x801120B4)` (`0x2C` bytes), but
its type-2 and type-6 taken branches leave that generated range and enter
adjacent pieces at `0x801120B4` and `0x801120EC`. Both pieces inherit live
entry registers (`a0` copied to `a2`, the record pointer in `v1`, and caller
`ra`), perform the selected swaps, and return directly through the original
`ra`. Neither has an independent prologue, ABI, or caller.

Consequently the exact logical owner is the contiguous interval
`[0x80112088,0x80112124)`, `0x9C` bytes, comprising generated ranges:

```text
0x80112088..0x801120B3  selector / unchanged return
0x801120B4..0x801120EB  type-2 swap and return
0x801120EC..0x80112123  type-6 swap and return
```

The next independent owner begins at `0x80112124`. Dispatch entries
`0x801120A4` and `0x801120AC` are ordinary internal branch/return blocks.
There are no direct calls to `0x801120B4` or `0x801120EC`; each is reached only
by the corresponding conditional branch from the true entry.

## Caller census

Eight generated call instances collapse to four unique executable call sites:

```text
0x800E624C
0x800E654C
0x80110C7C
0x80110CE8
```

The first two are mirrored expansion-RAM copies of the latter two conversion
paths. Every call targets `0x80112088` and passes the address of a stack word
containing the current record pointer (`sp+0xA4` in the mirrored loader and
`sp+0x1C` in the main-image converter). No executable caller targets an
interior address.

## Behavior and effects

For type 2, byte pairs `[8,9]` and `[12,13]` are exchanged. For type 6, byte
pairs `[4,5]` and `[8,9]` are exchanged. Treating each pair as an opaque U16
field is important: unlike adjacent `ByteSwapTwoU16Values`, this routine keeps
the order of the two bytes within each field. All other type values are a
no-op.

The call sites sit in packed resource/material conversion paths beside
`SwapRgb24RedBlue` and `ByteSwapTwoU16Values`. That context establishes a
type-specific packed-record layout conversion, but does not by itself prove
that the exchanged U16 fields are vertex indices; the conservative symbol
therefore names only the directly evidenced operation. The routine touches no
globals or hardware and performs no calls.
