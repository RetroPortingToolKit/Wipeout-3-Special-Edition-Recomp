# Semantic audit: `0x80110894` / `PrepareFrontendImageResource`

## Result and boundary

`0x80110894` is `PrepareFrontendImageResource`, a frontend image-loading and
layout pipeline used from the race/frontend transition owner. The generated
table proves its exact owner as `[0x80110894, 0x801109BC)`, `0x128` bytes and
16 blocks. It creates a 40-byte frame, returns at `0x801109B4`, and restores
the frame in the delay slot at `0x801109B8`; `0x801109BC` is independent.

## ABI

Only original `a3` is semantically consumed. It is retained in `s3` and its
byte at `+5` is passed to both private layout/build calls. Original `a0..a2`
are overwritten without being read. The effective ABI is therefore:

```c
void PrepareFrontendImageResource(
    uint32_t ignored0, uint32_t ignored1, uint32_t ignored2,
    const void *options);
```

The epilogue moves the never-assigned saved `s4` into `v0`; that is an
incidental incoming-register value, not a meaningful return contract.

## Behavior and state

The routine first calls `AcquireCurrentArchiveEntry(0)`. From the returned
image/resource block it reads a selector nibble from byte `+0x40`, uses it to
select a halfword at `resource + 0x14 + 2*nibble`, and expands that RGB5 value
to three multiples-of-eight. Each component below 9 is raised by 4, matching
the usual midpoint-biased 5-to-8-bit expansion. The components are published
to bytes `0x801DEE74`, `0x801DEE78`, and `0x801DEE7C`.

It then:

1. calls `CreateTextureDescriptorFromImageData(resource, 0)`;
2. releases tracked temporary archive blocks;
3. reacquires the current archive entry with policy 0;
4. calls private owner `0x8012DA10` with the archive data, texture descriptor,
   and `options[5]`;
5. releases tracked temporary blocks again; and
6. calls private owner `0x8012DCB4` with fixed workspace `0x801D7658`, the
   descriptor, and the same option byte.

The name remains conservative because the two `0x8012Dxxx` builders are not
yet independently named. The proven archive-image input, texture descriptor,
RGB tint publication, option byte, and adjacent frontend draw context support
“frontend image resource” without asserting a specific screen or artwork.

## Callers and target proof

There is exactly one direct call, at `0x80122890` inside the retained frontend/
race-frame owner. It passes its option record in `a3`. No direct call or jump
targets any interior block of `[0x80110898,0x801109BC)`, and no overlay or
duplicate-body instance exists.

The complete direct callee set is `AcquireCurrentArchiveEntry` twice,
`ReleaseAllTrackedTempHeapBlocks` twice,
`CreateTextureDescriptorFromImageData`, `0x8012DA10`, and `0x8012DCB4`.
