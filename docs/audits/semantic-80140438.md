# Semantic audit: `0x80140438`

## Result

`0x80140438` is a leaf effect-record producer, conservatively named
`EnqueueEffectInstance`. It advances a byte-wrapped pool index, fills one
48-byte effect instance from seven caller parameters, marks it active, and
returns success.

## Boundary and ABI

The generated manifest gives exact owner range `0x80140438..0x801404FF`
(0xC8 bytes). The next independent owner begins at `0x80140500`. The body is
one straight-line 50-instruction block ending in `jr $ra`; there is no padding,
split suffix, call, branch, stack frame, or interior target.

An evidence-shaped prototype is:

```c
int EnqueueEffectInstance(
    uint8_t type,
    const uint32_t position[3],
    const void *vector_a,
    const void *vector_b,
    const uint32_t *source_word,
    uint32_t parameter,
    uint8_t subtype);
```

The first four parameters use `$a0..$a3`; the source pointer, word parameter,
and subtype byte are read from caller stack slots `sp+0x10`, `sp+0x14`, and
`sp+0x18`. `vector_a` and `vector_b` each contribute unsigned halfwords at
offsets 0, 4, and 8, so the audit deliberately does not claim a packed SDK
vector type. The function always returns integer 1.

## Pool and record behavior

Word `0x801E1F14` points at the effect pool. The word at pool offset zero is
incremented and truncated to eight bits, then written back. The selected record
is:

```text
record = pool + 4 + 48 * new_index
```

The resulting fixed layout is:

| Offset | Value |
| --- | --- |
| `+0x00,+0x04,+0x08` | three words copied from `position` |
| `+0x10,+0x12,+0x14` | halfwords from `vector_a + 0,+4,+8` |
| `+0x18,+0x1A,+0x1C` | halfwords from `vector_b + 0,+4,+8` |
| `+0x20` | word loaded through `source_word` |
| `+0x24` | zero |
| `+0x28` | caller `parameter` |
| `+0x2C` | zero |
| `+0x2D` | low byte of `type` |
| `+0x2E` | caller `subtype` |
| `+0x2F` | one (active/default flag) |

The byte wrap means the producer reuses slots modulo 256; it performs no
capacity, null, or bounds check. Its only state effects are the pool index and
selected record writes. It touches no GPU, GTE, MMIO, COP0, or external helper.

`0x800EF79C`, `0x8011F07C`, `0x8011F5A8`, `0x8011FF60`, `0x80139560`,
`0x8015997C`, `0x8015B0C8`, and `0x8015B140`.

`0x8015997C` occurs in two generated overlay variants, accounting exactly for
the duplicate. Every call targets the true entry `0x80140438`; the single-block
body has no interior targets and there are no data-derived false callers.
