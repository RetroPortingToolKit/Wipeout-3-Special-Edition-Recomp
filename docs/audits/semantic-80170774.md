# Semantic audit: guest `0x80170774`

## Result

`0x80170774` is a real callable renderer entry, reached as the mode-3 tail
target of `DispatchPackedFacePrimitive`.  The defensible name is:

```text
SubdivideTwiceAndSubmitPackedFaceStrip
```

For each selected 64-byte face record, it projects a run of packed vertex
pairs.  Each adjacent pair-to-pair quad is subdivided at its edge midpoints
and center, and each of those four children is subdivided once more.  The
routine consequently invokes the selected primitive callbacks for as many as
sixteen leaf quads per accepted source quad.

## Boundary and reference evidence

- The entry has an explicit scratchpad frame at `0x1F8003CC`.  It saves `ra`,
  inherited `fp`, `s0..s7`, and `gp` at `0x80170774..0x801707AC` and restores
  them before `jr $ra` at `0x80170B54` (delay slot `0x80170B58`).
- The generated base range is exactly `0x80170774..0x80170B5B`, `0x3E8`
  bytes.  `0x80170B5C` starts a separate function with its own conventional
  80-byte stack frame.
- The base executable contains no direct `j`, `jal`, or aligned address word
  for `0x80170774`.  Instead, the dispatcher constructs the address in `$t6`
  at `0x8016FC58..0x8016FC5C`; selector 3 copies it to the final jump register.
  The original caller's `$ra` is preserved across that tail jump.
- Thus the entry is callable and returning, but its only established reference
  uses a renderer-private indirect tail ABI rather than an o32 call site.

## Private ABI and setup

The inherited inputs match the sibling packed-face renderers:

```text
$a0  section owner / transform-bearing render object
$a1  low-10-bit face-record index
$a2  consecutive face-record count (1..8)
$at  0x1F800010, after four callback words installed by the dispatcher
```

The entry preserves `$a1/$a2` in `$s0/$s1` and calls the shared renderer setup
at `0x801701B4`.  That setup resolves the indexed 64-byte face record, source
vertices, packed-pair descriptors, ordering table, packet cursors, transform
addends, and screen bounds.  The entry adds 60 bytes to the template-bank base
selected by the setup before doing visibility work; this is a fixed
mode-specific material offset, not a packet allocation.

For every face record, `u16 +0x34` indexes the 24-byte packed-pair table and
`u16 +0x36` supplies its quad count.  `ProjectPackedVertexPairs` at
`0x80170254` produces `count + 1` adjacent projected pairs in 16-byte vertex
records and returns their common screen outcode.  A nonzero result rejects
the whole record.  The outer loop advances the face pointer by 64 bytes and
runs for the inherited `$a2` count.

## Two subdivision levels

For each of the `count` pair-to-pair quads, the routine first ANDs the four
corner outcodes; a common bit rejects that quad.  Otherwise it calls
`BuildProjectQuadMidpoints` (`0x801704F0`) on the original corners.  That
helper writes four projected edge midpoints plus the projected center to an
80-byte scratch workspace.

The resulting four first-level children are processed in turn.  Each child is
again common-outcode tested and, if potentially visible, passed through
`BuildProjectQuadMidpoints` a second time.  Four callback calls then submit
that child's four grandchildren.  Across all four children this is at most
`4 * 4 = 16` leaf submissions for one source quad.  The repeated pointer
patterns at `0x80170850..0x80170AE8` prove this is geometric two-level
subdivision, not a single subdivision followed by sixteen unrelated packets.

Callback addresses are loaded from scratchpad words 0 and 1.  Mode 3 leaves
both words equal to `0x801700C4`, so observed dispatch uses
`SubmitTexturedQuad` for every leaf; describing the calls as callbacks retains
the actual private contract.  The material/texture-template cursor advances
by 12 bytes after each leaf call.  Its base is selected from the table at
`0x801E2724` using byte `descriptor + 0x0E` with a 504-byte stride and bit 2 of
byte `+0x0F` selecting the second 252-byte half, as in the sibling renderer.

This function itself does not construct a GPU primitive or link an ordering
table entry.  Projection is delegated to the two projection helpers, and leaf
packet emission, near clipping, and OT linkage are delegated to the selected
callback.  On completion it publishes the updated packet cursors at
`0x801E5668` and `0x801E5664`.

## Symbol decision

- Add `0x80170774` as `[[func]] SubdivideTwiceAndSubmitPackedFaceStrip`.
- Mark it `known`: boundary, unique selector reference, record traversal,
  two-level subdivision, callback count, and cursor publication are direct
  instruction-level facts.
- Keep `emit = false`: it depends on scratchpad callback state, private live
  registers, and dispatcher-owned tail-call return semantics.
