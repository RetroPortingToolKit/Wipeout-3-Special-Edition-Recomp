# Semantic audit: `0x80170254`

## Conclusion

`0x80170254` is a real callable leaf function, not an internal block.  The
defensible name is `ProjectPackedVertexPairs`.  Its generated AOT extent is
`0x80170254..0x801704EF` (668 bytes), with loop/re-entry blocks at
`0x801703A4` and `0x801704E4`.

It consumes packed vertex-index pairs through a renderer-private register ABI,
builds two projected 16-byte records per pair, and returns the bitwise AND of
all generated screen clip codes. It emits one initial pair plus one pair for
each counted 24-byte descriptor, so a count of N produces N+1 adjacent pairs.
The old `ProjectPackClipCodes` name was too narrow: projection and expansion
into an output record array are primary effects, while clip-code aggregation
is its return value.

## Call and boundary evidence

- The instruction immediately before the entry belongs to the preceding leaf,
  which returns through `jr $ra` at `0x8017024C` (delay slot `0x80170250`).
- The body returns through `jr $ra` at `0x801704E8` (delay slot
  `0x801704EC`).  It does not allocate a conventional stack frame and makes no
  calls.
- The base image has exactly two direct JAL sites, at `0x8016FAE4` and
  `0x801707E0`; their return PCs are `0x8016FAEC` and `0x801707E8`.
- AOT dispatch metadata independently identifies a 668-byte, three-block
  function rooted at `0x80170254`, with resumable blocks `0x801703A4` and
  `0x801704E4`.

## Renderer-private register convention

The two callers establish the same live-register contract.  These are not
normal o32 arguments, so a future C lift must use an adapter or lift the callers
with it.

| Register | Role established by the body |
| --- | --- |
| `$t4` / `$12` | Packed-pair descriptor cursor; the first word is read at `+4` |
| `$t3` / `$11` | Positive descriptor/segment count; output contains one additional initial pair |
| `$gp` / `$28` | Output cursor, advanced by 32 bytes for every emitted pair |
| `$s6` / `$22` | Base of 12-byte signed-XYZ source vertices |
| `$t0..$t2` / `$8..$10` | XYZ addends applied before arithmetic divide by two |
| `$fp+44`, `$fp+48` | Signed screen X and Y upper bounds |
| `$v0` / `$2` | Return accumulator: AND of every emitted clip code |

The routine temporarily preserves `$s0` and `$k1` in GTE-independent HI/LO,
then restores them on return.  `$t9` and `$t8` become the descriptor cursor and
loop counter internally.

## Data flow and record layout

For each emitted pair the routine extracts two unsigned 16-bit indices from
one 32-bit word. An index is multiplied by 12 and added to `$s6`. For each
selected vertex it computes:

```text
work.xyz = (source[index].xyz + { $t0, $t1, $t2 }) >> 1
```

The signed XYZ halves are fed to GTE `RTPS`.  Each output element is 16 bytes:

| Offset | Width | Meaning |
| --- | --- | --- |
| `+0,+2,+4` | 3 x s16 | Averaged camera-space XYZ input |
| `+8` | u32 | GTE `SXY2` projected screen coordinate |
| `+12` | u16 | GTE `SZ3` depth |
| `+14` | u16 | Screen clip bits |

The pair occupies 32 bytes.  Clip bits are constructed as RIGHT=`1`, LEFT=`2`,
BOTTOM=`4`, TOP=`8`, using signed X/Y against zero and the two bounds.  `$v0`
starts at `0xF` and is ANDed with both elements' codes, then with every later
pair.  This is a trivial-reject summary: a nonzero returned bit means every
projected point lies beyond that same screen edge.

Before the counted loop, the routine emits an initial pair from
`descriptor + 4`. It then executes exactly `$t3` iterations beginning with a
word at `descriptor + 0`, advances the descriptor cursor by 24 bytes after
each iteration, and emits one pair per iteration. The output is therefore
`32 * ($t3 + 1)` bytes. That asymmetry is explicit in the machine code and is
what lets `0x8016FA70` form `$t3` quads between adjacent pairs; it should be
preserved until the owning descriptor structure is named from broader
evidence.

## Confidence limits

Projection, record layout, clip-bit meanings, callability, callers, and loop
extent are directly established and therefore `known`.  The higher-level type
and why the first packed pair is at `+4` remain unnamed; the symbol deliberately
does not claim a polygon topology or gameplay object type.
