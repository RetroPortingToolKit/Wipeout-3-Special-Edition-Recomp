# Semantic audit: `0x80138188` / `RestoreCdCallbackConfiguration`

## Result and boundary

`0x80138188` is the CD-state initializer now conservatively named
`RestoreCdCallbackConfiguration`:

```c
int RestoreCdCallbackConfiguration(void);
```

The generated owner is exactly `0x80138188..0x801381D7` (0x50 bytes). It is a
normal framed function with five basic blocks, restores `ra`, and returns from
`0x801381D0` with the stack adjustment in the delay slot. The independent
owner at `0x801381D8` is not part of it. Generated dispatch continuations at
`0x801381A0`, `0x801381A8`, `0x801381B0`, and `0x801381C0` are resumable blocks,
not separate functions.

## Exact behavior

The incoming argument registers are unused. The routine performs this fixed
sequence:

1. Calls confirmed `CdControlWithRetry(1, NULL, NULL)`. Its return value is
   ignored; command byte 1 is therefore a synchronous CD-state probe/reset
   step here rather than a success predicate.
2. Calls the 0x14-byte callback exchanger at `0x80160D14` with null. That leaf
   replaces the callback word at `0x801792C8` and returns its prior value; the
   returned value is ignored.
3. Calls confirmed `CdReadyCallback(NULL)`, clearing the LibCD ready callback
   at `0x8017B128`; its prior callback result is also ignored.
4. Loads the saved callback pointer from `0x801D1B90` and passes it to confirmed
   `CdSyncCallback`, restoring `0x8017B124` to that value.
5. Stores 1 to the shared initialization flag at `0x8017627C`, sets `v0` to 1,
   and returns.

There are no conditional branches in the owner and none of the callback or CD
command return values can alter the final result. Thus the function always
returns exactly 1 after completing the sequence. Its direct state changes are
the three callback exchanges and the initialization flag; lower CD effects are
owned by `CdControlWithRetry`.

The callback at `0x801D1B90` is not guessed: the initialization path in owner
`0x80115FC0` stores the previous result of `CdSyncCallback(NULL)` there before
later users restore it. The conservative name describes the observable
configuration work without assigning an unproven original source identifier.

## Callers and entry integrity

Eight unique direct JAL sites target the true entry:

- `0x80112CC0`, `0x80112D9C`, and `0x80112E84`, in owner `0x80112C08`;
- `0x80113180` and `0x801132D4`, in owner `0x8011309C`;
- `0x8011375C`, in owner `0x8011364C`;
- `0x801226E4`, in owner `0x8012268C`;
- `0x80137C18`, in owner `0x80137BE4`.

The latter two callers explicitly read `0x8017627C` and invoke this routine
when it is zero, independently confirming the initialization/restore role.
No direct JAL targets any continuation or other interior address, and there are
no overlay-duplicate call instances among the eight sites.
