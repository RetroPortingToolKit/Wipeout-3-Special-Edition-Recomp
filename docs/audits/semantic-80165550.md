# Semantic audit: `0x80165550` / `ExitCriticalSection`

## Result

`0x80165550` is the PlayStation syscall wrapper `ExitCriticalSection`:

```c
int ExitCriticalSection(void);
```

It loads syscall selector 2 into `a0`, executes `syscall 0`, and returns through
the original `ra`. The platform syscall contract enables current interrupts
and the interrupt-controller mask in COP0 Status (IEc bit 0 and IM2 bit 10)
and returns zero in `v0`.

## Boundary and effects

The exact owner is `[0x80165550, 0x80165560)`, four instructions or `0x10`
bytes, in one frameless block. `0x80165560` begins an independent owner.

The wrapper has no RAM loads/stores, ordinary calls, globals, stack accesses,
or direct MMIO. Its only architectural mutation is delegated through syscall
2 to COP0 interrupt state. Unlike `EnterCriticalSection`, it does not preserve
or return the previous IEc value; its result is zero.

## Complete incoming proof

An aligned executable scan finds exactly fourteen JALs, all to the entry and
none to an interior instruction:

```text
801203D4 8015FE10 8015FE58 801613AC 80161D1C
80162764 80162B8C 80163CE0 80167030 80167284
801672C0 801693D4 8016946C 8016B8A0
```

The caller set includes CD, GPU, SIO, and SPU library paths that pair interrupt
exclusion with the separately recovered enter wrappers.

## Confidence

`confirmed`: selector, syscall, exact range, COP0 contract, return, effect
boundary, all callers, and absence of interior targets are instruction-proven
and independently reflected by the runtime's syscall implementation.
