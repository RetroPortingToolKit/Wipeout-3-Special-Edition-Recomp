# Semantic audit: `0x80106518` / `DrawRaceStatusHud`

## Result

`0x80106518` is the large race-status HUD owner now named
`DrawRaceStatusHud`:

```c
void DrawRaceStatusHud(void *unused, RuntimeRacer *racers);
```

It derives race/placement display state from the 15-racer runtime array and
current-player globals, then conditionally emits the position, numeric status,
race times, text labels, and several textured HUD quads.

## Exact logical owner and false splits

The true function is `[0x80106518,0x801078D4)`, exactly `0x13BC` bytes. It
opens one `0x88`-byte frame at `0x80106518`, preserves `ra`, `fp`, and
`s0..s7`, and does not restore them until `0x801078A4..0x801078C8`. The sole
return is at `0x801078CC` with stack restoration at `0x801078D0`; the next
genuine function opens its own `0x50`-byte frame at `0x801078D4`.

Generated metadata incorrectly exposes the continuous owner as:

```text
80106518 +5D4   80106AEC +004   80106AF0 +0F0
80106BE0 +138   80106D18 +004   80106D1C +12C
80106E48 +A8C
```

`0x80106AEC` is the delay-slot instruction of the preceding branch. The later
pieces use the original frame and saved registers; forward branches enter
`0x80106AF0`, `0x80106BE0`, `0x80106D18`, `0x80106D1C`, and `0x80106E48`.
None has a prologue or independent return. These are control-flow splits, not
seven functions.

## ABI and race-state inputs

Original `a0` is overwritten by a constant before any read and is unused.
`a1` is a runtime-racer array: the entry loop examines word `+0xEC` of 15
records at exact stride `0x16C`, counting records whose `0x8000` flag is
clear. This independently matches the recovered runtime-racer layout.

The owner reads the current player/view pointer at `0x801A5840`, including its
player/racer selector bytes and status/timer words. It also consults race mode,
viewport, track/session, localized-resource, and layout tables. No purposeful
scalar return is established, and the only caller ignores register residue,
so the ABI is void.

## Rendering behavior

The control flow selects among race modes and current-player states, but its
rendering vocabulary is exact from the recovered callees:

- 18 call sites to `EmitFontGlyphPacket` render signed decimal fields, rank or
  count values, and separators using styles selected from HUD layout tables;
- four calls to `DrawRaceTimeCentiseconds` render race/lap time values with
  the fractional suffix disabled;
- four calls to `DrawAsciiTextString` render table-selected status strings;
- two calls to `DrawResourceString` render localized resource indices `0xCD`
  and `0x147` at X coordinate `0x1C` when their countdown/status gates permit;
- four calls to `EmitTexturedQuadPacket` build two pairs of HUD image quads,
  which this owner immediately splices into the active ordering table;
- one call to `IsRacerSlotVacant` filters the 15-entry race-record scan used
  to derive a competing placement/status byte.

The repeated decimal paths use exact signed divide-by-ten reciprocal
arithmetic, emit a minus glyph `0x28` for negative values, and emit up to five
digits through the fixed-neutral-gray glyph renderer. Packet construction is
delegated: glyph, string, time, and resource callees allocate/OT-link their
own packets, while the four textured-quad returns are explicitly linked here.

The late localized-message paths decrement current-player words `+0x358` and
`+0x35C` by three after drawing. Apart from those countdown changes, the owner
primarily reads race state; render mutations are packet-cursor advances,
packet writes, and ordering-table links performed directly or through the
confirmed callees.

The conservative `RaceStatusHud` name reflects the proved mix of rank/count,
times, strings, and HUD images. It does not claim that this is the complete
race HUD: its sole caller invokes several adjacent HUD owners afterward.

## Caller and target census

There is exactly one executable entry call, `0x8010D4A8`. It occurs in the
race-view HUD pipeline between the genuine owners at `0x801078D4` and
`0x80107E18`, passes the runtime-racer array as `a1`, and ignores the return.
Generated output emits that call once.

No executable J/JAL targets an interior address. An aligned raw-word scan does
find a JAL-shaped word at `0x800AB0B4` targeting `0x80106AEC`, but that source
lies in non-code data: it has no generated instruction/owner or surrounding
decodable code, and its target is demonstrably a branch delay slot dependent
on this owner's live frame. It is not an executable caller.
