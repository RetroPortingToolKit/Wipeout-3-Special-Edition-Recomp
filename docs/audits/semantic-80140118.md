# Semantic audit: `0x80140118`

## Result

`0x80140118` is the shared four-vertex layout tail inside the real function
owner at `0x80140000`. It is not a standalone source-level function despite the
generated `func_80140118` and alias wrappers.

Catalog block name: `PrepareFourVertexPrimitiveLayoutTail` (`confirmed`).

## Exact owner and boundary

The owner begins at `0x80140000` with an 80-byte stack frame and saved
`ra/s0..s7/fp`. It has one return epilogue at `0x801403BC..0x801403E8`, so its
exact half-open extent is `0x80140000..0x801403EC` (1004 bytes).

The apparent generated functions at `0x80140074`, `0x80140110`,
`0x80140118`, and their aliases are control-flow split artifacts. In
particular, `0x80140118..0x80140143` contains three generated blocks because
the recompiler accepts internal resume/alias entries at `0x80140124` and
`0x80140134`; none has a prologue or return.

## Caller and control-flow proof

The executable contains one direct call to the owner:

- `0x8013EA6C: jal 0x80140000`
- arguments at the call are `a0 = caller object`, `a1 = 2`,
  `a2 = sp + 0x10`, and `a3 = sp + 0x30`.

There is no direct `jal 0x80140118`. Its real predecessors are two jump-table
cases selected from the primitive type byte at `[s1 + 0]`:

- type 4: `0x801400FC` jumps directly to `0x80140118`, with
  `s2 = s1 + 0x10` in the delay slot;
- type 7: `0x80140114` first sets `s2 = s1 + 4`, then falls through to
  `0x80140118`.

The eight-entry jump table at `0x8016E800` is, in type order 1 through 8:
`400CC, 400EC, 400DC, 400FC, 40104, 40124, 40114, 40134`.

## Behavior

At `0x80140118`, the shared tail performs exactly:

```text
s4 = 4
j 0x80140168
  s1 += 0x18                 # delay slot
```

Thus types 4 and 7 both describe a 24-byte packed primitive with four vertex
indices, but use different index-array offsets (`+0x10` versus `+4`). The
common continuation scans the owner's primitive records, resolves each chosen
index through the vertex table at owner+`0x18`, writes four XYZ triples to the
`a2` output, sums their signed 16-bit coordinates, divides each sum by four,
and writes the resulting centroid XYZ to `a3` when exactly one mask-matching
record was found.

## Recompiler implication

Keep this as a `[[block]]`, not a callable `[[func]]`. Naming the address is
useful for coverage and traces, but emitting it as a host-callable replacement
would incorrectly require the owner's live callee-saved state (`s1`, `s2`,
`s4`, `s5`, `s6`, `s7`) and would canonize a generated split as an ABI
boundary.
