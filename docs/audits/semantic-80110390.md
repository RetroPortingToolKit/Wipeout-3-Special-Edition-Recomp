# Semantic audit: `0x80110390` / `RotateQuadCoordinatesCounterclockwise`

## Result and ABI

`0x80110390` is the counterclockwise member of the recovered quad-coordinate
permutation family:

```c
void RotateQuadCoordinatesCounterclockwise(
    int16_t *x0, int16_t *y0, int16_t *x1, int16_t *y1,
    int16_t *x2, int16_t *y2, int16_t *x3, int16_t *y3);
```

The first four pointers arrive in `a0..a3`; the final four are stack arguments
at incoming `sp + 0x10..0x1C`. The routine snapshots every signed halfword
before its first output store, so aliased pointers cannot corrupt later reads.

Using the row-major corner topology established by the adjacent horizontal and
vertical mirror helpers,

```text
[0 1]     [1 3]
[2 3]  -> [0 2]
```

or, as destination-from-source indices, `(0,1,2,3) <- (1,3,0,2)`. Source
corner movement is `0 -> 2 -> 3 -> 1 -> 0`, which is a counterclockwise
quarter-turn. This is the inverse of confirmed sibling
`RotateQuadCoordinatesClockwise` at `0x80110324`.

## Boundary and effects

The owner is exactly `0x80110390..0x801103FB` (0x6C bytes). The independent
owner at `0x801103FC` is excluded. It is call-free and branch-free, and no
external control-flow target enters an interior instruction.

All loads and stores are halfword operations. Exact 16-bit patterns are
preserved despite signed loads; there is no arithmetic, clamping, allocation,
global access, or hardware effect.

## Callers

Three unique JAL sites target the true entry:

- `0x8010B310`;
- `0x8010B35C`;
- `0x8010BEEC`.

There are no overlay duplicates or interior targets.
