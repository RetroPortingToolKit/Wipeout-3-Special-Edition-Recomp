# Semantic audit: `0x80162474`

## Result

`0x80162474` is the exact PS-X EXE entry point and a two-instruction,
non-returning startup trampoline.  The defensible symbol is
`PsxExeEntryTrampoline`, with `status = "confirmed"`.  It is a real external
entry boundary, but it is not the game's C `main`, a normal o32 callable
function, or the body that performs CRT initialization.

## Boundary and reachability evidence

- The `PS-X EXE` header at file offset `0x10` contains `0x80162474`.  The
  executable header also specifies load address `0x80010000`, text size
  `0x0016C000`, and initial stack `0x801FFFF0`.
- The entire executable contains no encoded `j` or `jal` to `0x80162474` and
  no other stored pointer equal to it.  Its sole stored address is the header
  entry field.
- The preceding code is a distinct BIOS wrapper at `0x80162464`:
  `li $t2,0xB0; jr $t2; li $t1,0x5B`.  Its sequential padding at
  `0x80162470` does not flow into the entry because the indirect jump has
  already transferred control to the BIOS vector.
- The complete entry body is:

  ```mips
  80162474  j     0x800D03B8
  80162478  addiu $v0,$v0,-0x4160   # jump delay slot
  ```

  It has no prologue, saved return address, arguments, or return path.

## Startup path and responsibilities

The entry transfers to an embedded startup loader at `0x800D03B8`.  That
loader probes expansion-RAM aliasing with sentinel words at `0x800D05B4`,
`0x802D05B4`, and `0x806D05B4`.  When the probe succeeds it:

1. copies `0x7BC` words from `0x800D05B8` to `0x80780000`;
2. applies `0x1DC` destination/value relocation pairs from `0x800D24A8`;
3. calls `0x80168D18` before joining the common startup path.

Both probe outcomes set `$v0 = 0x8017BEA0` and jump to `0x8016247C`.  The
routine beginning there, rather than `0x80162474`, performs the recognizable
CRT work: it clears memory through `0x801EEBCC`, derives the stack and heap
bounds from linker words at `0x80174940`/`0x80174944`, records `$ra`, sets
`$gp = 0x8017BE3C` and `$fp = $sp`, invokes BIOS service A0/39 through
`0x80168D48`, and then continues into program startup at `0x80116128`.

The entry's delay-slot adjustment of the incoming `$v0` is not sufficient to
describe an ABI contract: the loader overwrites `$v0` on every join path.
Accordingly this symbol should remain `emit = false` and must not be exposed
as an ordinary host-callable o32 function.

## Naming decision

`BootEntry` was directionally correct but too broad: it implied that the
two-instruction symbol owned initialization that actually resides in the
loader and the `0x8016247C` CRT body.  `PsxExeEntryTrampoline` captures both
the authoritative header role and the limited semantics of this boundary.
