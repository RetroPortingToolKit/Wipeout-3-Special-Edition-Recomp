# Semantic audit: `0x80110324` / `RotateQuadCoordinatesClockwise`

## Result and ABI

`0x80110324` is `RotateQuadCoordinatesClockwise`, the clockwise quarter-turn
member of the eight-pointer quad-coordinate permutation family:

```c
void RotateQuadCoordinatesClockwise(
    int16_t *x0, int16_t *y0, int16_t *x1, int16_t *y1,
    int16_t *x2, int16_t *y2, int16_t *x3, int16_t *y3);
```

Pointers 0 through 3 arrive in `a0..a3`; pointers 4 through 7 are incoming
stack arguments `+0x10..+0x1C` before the eight-byte frame. The leaf provides
no scalar return value.

## Boundary and permutation

The generated table proves the exact interval `[0x80110324, 0x80110390)`,
`0x6C` bytes. This is a one-block leaf preserving `s0/s1`; it returns at
`0x80110388`, restores the frame in the `0x8011038C` delay slot, and is
followed by the independent owner at `0x80110390`.

All eight signed halfwords are snapshotted before stores. Grouping them into
four `(x,y)` corner pairs, the exact permutation is:

```text
(P0,P1,P2,P3) -> (P2,P0,P3,P1)
[[P0,P1],      -> [[P2,P0],
 [P2,P3]]          [P3,P1]]
```

That is a clockwise quarter-turn of the 2x2 corner assignment. Unlike
`MirrorQuadHorizontalCoordinates`, which exchanges X components only, and
`MirrorQuadVerticalCoordinates`, which exchanges Y components only, this
routine moves complete coordinate pairs. Halfword stores preserve every input
bit pattern; there are no calls, globals, GPU writes, or validation effects.

## Callers and targets

Exactly two executable calls target the entry:

```text
0x8010B2A0  0x8010BE88
```

Both callers supply the same eight coordinate pointers used by the neighboring
orientation helpers. No direct call or jump targets an interior instruction,
and the body has no overlay duplicate. The exact pair movement, shared ABI,
and orientation-selection caller context support the directional rotation
name rather than a generic permutation label.
