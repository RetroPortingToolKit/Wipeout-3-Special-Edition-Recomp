# Semantic audit: `0x80134964`

## Result

`0x80134964` is a callable 136-byte leaf predicate, named
`IsRaceRecordStatusZeroTypeOne` in the symbol catalog. It accepts a signed racer index
and returns one exactly when the selected record has byte `+0 == 0` and byte
`+3 == 1`; it returns zero for a negative index or either failed field test.

The name deliberately captures the stable domain evidence without assigning a
more specific meaning to the type-one state. Calls consistently use racer
indices, including the racer index stored at `+0x53` in effect records. The
precise meanings of the two leading racer-record bytes remain unnamed.

## Boundary and control-flow proof

- The previous leaf returns through `jr ra` / `nop` at
  `0x8013495C..0x80134960`.
- The audited entry begins independently at `0x80134964` with `move a1,a0` and
  does not use the preceding routine's state.
- Its only exits join the `jr ra` / `nop` pair at
  `0x801349E4..0x801349E8`.
- The next independent leaf begins at `0x801349EC`. Thus the exact callable
  interval is `[0x80134964,0x801349EC)`, or `0x88` bytes.
- Generated resumable blocks at `0x80134970`, `0x801349A4`, `0x801349AC`,
  `0x801349E0`, and `0x801349E4` are internal control-flow labels, not ABI
  entries.

## Record indexing and predicate

For a nonnegative input `i`, the address arithmetic is:

```text
t = ((i * 8 - i) * 4 + i) * 8 + i
record = 0x801910E0 + t * 4
       = 0x801910E0 + i * 0x3A4
```

The first `lb` reads `record[0]`. The `sltiu value,1` instruction is true only
for zero (negative signed-byte values become large unsigned values), so any
nonzero byte exits false. Only a zero first byte reaches the second `lb`, which
reads `record[3]`; the routine returns one only when that value equals one.
In source-like form:

```c
return i >= 0 && racer[i].byte_0 == 0 && racer[i].byte_3 == 1;
```

The `0x3A4` stride independently agrees with the racer/view-record arithmetic
recovered in the `0x80133B64` initialization audit. Its published viewport
subobject begins at `0x80191114`, which is `0x34` bytes into the same first
record.
