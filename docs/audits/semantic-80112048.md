# Semantic audit: `0x80112048`

## Result

`0x80112048` is the leaf `SwapRgb24RedBlue`:

```c
void SwapRgb24RedBlue(uint8_t rgb[3]) {
    uint8_t red = rgb[0];
    uint8_t blue = rgb[2];
    rgb[0] = blue;
    rgb[1] = rgb[1];
    rgb[2] = red;
}
```

The explicit middle-byte load/store is retained above because it is present in
the executable, even though it is semantically an identity write.  The routine
is an in-place RGB/BGR channel-order conversion and has no scalar return value.

## Boundary proof

The generated range manifest records `R 80112048 1C`, exactly seven
instructions.  The instruction sequence is:

| PC | instruction | effect |
| --- | --- | --- |
| `0x80112048` | `lbu v1,2(a0)` | load byte 2 |
| `0x8011204C` | `lbu a1,0(a0)` | load byte 0 |
| `0x80112050` | `lbu v0,1(a0)` | load byte 1 |
| `0x80112054` | `sb v1,0(a0)` | byte 2 -> byte 0 |
| `0x80112058` | `sb v0,1(a0)` | preserve byte 1 |
| `0x8011205C` | `jr ra` | return |
| `0x80112060` | `sb a1,2(a0)` | byte 0 -> byte 2 in the delay slot |

The following address, `0x80112064`, is independently advertised as another
function and starts a distinct four-byte permutation.  There is no branch,
fallthrough, stack frame, or shared epilogue joining the two routines, so the
`0x1C` boundary is exact.

## Caller proof

A word-aligned scan of the loaded PS-X EXE image for direct `jal 0x80112048`
finds exactly eight encoded call instructions:

- main-image calls at `0x80110C4C`, `0x80110C74`, `0x80110CAC`, and
  `0x80110CD4`;
- mirrored expansion-RAM calls at `0x800E6104`, `0x800E6244`, `0x800E63BC`,
  and `0x800E6538`.

At the four main-image sites the delay slots pass `a1 + 4`, `a1 + 16`,
`a1 + 4`, and `a1 + 12`, respectively, as `a0`.  Those offsets select embedded
three-byte color fields in the caller's packet/material records.  The mirrored
call sites are copies of the same conversion paths rather than additional
semantics.

## Confidence

Status is `confirmed`: the complete function is a straight-line permutation,
all direct callers are enumerable from the executable, and both the exact
boundary and channel transformation follow directly from the seven machine
instructions.  The historical source-level spelling is not claimed.
