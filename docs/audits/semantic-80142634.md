# Semantic audit: `0x80142634`

## Result

`0x80142634` is a real callable boundary spanning `0x80142634..0x80144687`
(8,276 bytes).  The evidence supports the name
`ClipAndEmitSceneryPrimitive` with `confirmed` status.  The older
`SceneryFrustumClip` name described only the first half of the routine: this
function also projects, triangulates, creates GPU packets, links them into the
ordering table, and advances the primitive arena.

## ABI and callers

The routine has a normal 560-byte stack frame and saves `s0..s7`.  It takes no
meaningful o32 argument and has no meaningful scalar return value.  At
`0x80142654` it overwrites `a0` with `0x801e0000`, and at `0x801426a8` it copies
that value into `s7`; callers do not consume `v0` after return.  Inputs and
outputs are therefore global-workspace based.

There are 39 statically emitted `jal 0x80142634` sites, owned by the following
recompiler roots:

- `0x80170b5c` (`ClipAndSubmitNearTexturedQuad`), return `0x80170c64`;
- `0x801719dc`, return `0x80171a5c`;
- the overlapping suffix roots `0x80172984`, `0x80172a24`, `0x80172ac4`,
  `0x80172b54`, `0x80172be4`, `0x80172c64`, `0x80172cec`, and `0x80172d64`.

The suffix roots are progressively shorter entries into one unrolled marshal
sequence, not 36 independent high-level callers.  Each entry copies another
vertex/material record into the shared workspace and calls this routine.  The
two standalone call paths likewise marshal the workspace before calling it.

## Workspace contract

The fixed workspace begins at `0x801e25d0`.  Entry reads at least these fields:

- `+0x14`: source vertex/table pointer;
- `+0x18..+0x44`: four 12-byte vertex/attribute records selected by packed
  indices;
- `+0x4c`: material/texture word;
- `+0x50`: signed input vertex count/control value;
- `+0x52`: primitive mode bits;
- `+0x53`: material/render flags.

The routine copies the polygon into two alternating local buffers inside its
560-byte frame.  Generated vertices carry camera-space coordinates together
with the texture and color attributes needed by the later packet builders.
Intersection vertices interpolate all of those fields rather than only XYZ.

## Clipping behavior

This is Sutherland-Hodgman clipping against the four camera side planes.  It
walks every edge, emits an endpoint when it remains inside, and emits an
interpolated intersection when an edge crosses a plane.  Empty intermediate
polygons terminate without allocating a GPU primitive.

Plane distances use the shared viewport coefficients loaded at entry:

- `0x801e25cc`: common X/Y axis coefficient;
- `0x801e2488`: horizontal depth coefficient;
- `0x801e2480`: vertical depth coefficient;
- `0x801e2484`: the paired side-plane coefficient.

When `0x801e25d0 == 1`, all four coefficients are arithmetically halved before
clipping.  The tests are the signed fixed-point forms of `+/-x` versus depth
for left/right and `+/-y` versus depth for top/bottom.  This agrees with the
known producers of those coefficients and rules out a screen-coordinate
rectangle clipper.

## Projection and packet emission

After clipping, the surviving polygon is projected and emitted as a triangle
fan.  Mode/material bits choose among the textured packet commands visible in
the function:

- `0x24` / `0x26`: FT3, opaque / semitransparent;
- `0x2c` / `0x2e`: FT4, opaque / semitransparent;
- `0x34` / `0x36`: GT3, opaque / semitransparent;
- `0x3c` / `0x3e`: GT4, opaque / semitransparent.

Thus an unclipped four-vertex input can remain a quad, while polygons enlarged
by clipping are fan-triangulated.  Each packet receives projected XY, UV and
CLUT/TPAGE material fields; Gouraud paths additionally write per-vertex color.
The packet is linked into the depth ordering table, and the global primitive
cursor at `0x80198620` advances by the selected packet layout's size.  The
distinct emission paths visibly compute advances of 28, 32, 36, 40, or 52
bytes before the common cursor stores; this is packet-shape dependent, not a
single fixed allocation.  The final command byte is selected between the
opaque and semitransparent opcode immediately before the cursor update.

## Boundary evidence

- `0x80142634`: `addiu sp,sp,-560` and callee-save prologue.
- `0x80142634` is the target of direct `jal` instructions from the marshal
  paths above.
- `0x80144660..0x80144684`: restores `s0..s7`, executes `jr ra`, and releases
  the 560-byte frame in the delay slot.
- `0x80144688` starts a distinct 64-byte-frame function.

The boundary is therefore not a trace artifact or an internal label.
