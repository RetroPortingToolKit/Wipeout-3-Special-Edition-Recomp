# Semantic audit: `0x80104750` / `RecordRacerEliminationCredit`

## Result

`0x80104750` is the conditional elimination-statistics updater now named
`RecordRacerEliminationCredit`:

```c
void RecordRacerEliminationCredit(int victim_index, int credited_racer_index);
```

It verifies that the target racer is in the destruction state appropriate to
its slot class, then increments the credited racer's common elimination count
and one session-mode-specific byte count.

## Exact owner and ABI

The complete owner is `[0x80104750,0x80104858)`, exactly `0x108` bytes,
matching the generated range table. It opens a 0x20-byte frame, saves
`ra/s0/s1`, and all exits use the restore/return at `0x80104844..0x80104854`.
The preceding owner returns at `0x80104748`; the next independent initializer
creates its own frame at `0x80104858`.

The effective ABI is:

- `a0`: victim racer/slot index;
- `a1`: racer index receiving the elimination credit;
- incoming `a2` and `a3`: ignored. Callers commonly place an effect/event kind
  in `a2`, but this owner never reads it;
- no semantic return. Exit paths leave predicate or counter-address residue in
  `v0`, and every caller ignores it.

There is no bounds check on either index. Callers must provide valid racer
indices for the arrays accessed below.

## Suppression and victim-state gates

The first call is the shared predicate at `0x80134B60`. If it returns nonzero,
the function exits without changing a counter. That predicate scans current
racer/session records and can suppress this credit operation globally; its
broader name is left outside this audit.

The victim gate uses the confirmed `IsRacerSlotVacant` predicate at
`0x8013491C` and word array `0x801E9DA4[victim_index]`, previously recovered as
the racer destruction/disabled state:

```c
if (IsRacerSlotVacant(victim_index)) {
    if (gRacerDestructionState[victim_index] != 100)
        return;
} else {
    if (gRacerDestructionState[victim_index] != 15)
        return;
}
```

The executable redundantly calls `IsRacerSlotVacant` a second time on the
occupied path and returns if that second result changes to true. No callee in
between writes racer state, so this does not alter the ordinary formula, but
the repeated query is part of the exact instruction flow.

The distinct constants explain why the function cannot simply test a common
boolean disabled flag: it requires class-specific terminal state values.

## Counter effects

After the gates pass, the function always increments:

```c
(*(uint32_t *)(0x8017C484 + credited_racer_index * 4))++;
```

It then reads the session mode word at `0x80194B90`:

```c
if (session_mode == 7)
    (*(uint8_t *)(0x8018AD64 + credited_racer_index))++;

if (session_mode == 6)
    (*(uint8_t *)(0x8018ADA6 + credited_racer_index))++;
```

The two mode checks are sequential. Mode 7 increments only the first byte
array; mode 6 increments only the second. Other modes receive only the common
32-bit count. All increments wrap naturally at their storage width; there is
no saturation or overflow check.

No victim field, effect record, heap, controller, GPU, or audio state is
modified.

## Complete callers and interior targets

An exhaustive aligned instruction-word scan of the retained executable finds
exactly six direct calls:

```text
80150D08 80151E38 80152704
80155A90 80159538 8015ACF4
```

All six target `0x80104750`; there are no direct `j` or `jal` targets to an
interior address in `[0x80104754,0x80104858)`.

Caller windows are effect/damage terminal paths. They first check a related
per-victim word for value 100, pass the current victim index in `a0`, load the
credit index from effect-record byte `+0x53` (or an equivalent saved value),
and commonly load the unused kind byte `+0x54` into `a2`. After the call they
retire or advance the effect record and never consume `v0`.

Together with the destruction-state gate and per-racer statistics increments,
this supports elimination credit rather than a generic event counter.

## Confidence limits

The exact gates, constants, arrays, widths, modes, callers, and ignored third
argument are instruction-proven. The common word and two mode-specific byte
arrays are named by their elimination-credit role here; their original UI
labels (for example, distinctions among kill, knockout, or league statistics)
are not independently visible and are not claimed.
