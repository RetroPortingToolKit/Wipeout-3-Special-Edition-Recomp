# Semantic audit: guest `0x80136078`

## Conclusion

`0x80136078` is a genuine function boundary and is best described as
`InstallLinkedRenderTransform`. It follows a linked transform chain to its
terminal record, converts that record to the engine's projection-adjusted
scratch `MATRIX`, and installs the result in the GTE. It does not compose all
matrices in the chain.

The boundary and behavior are sufficiently explicit for `status = "known"`.
The name is descriptive rather than a claim about the original source symbol.

## Boundary, callers, and ABI

- The generated range is exactly `0x80136078..0x801361AB` (`0x134` bytes).
- The entry allocates 24 stack bytes and saves `s0` and `ra`; the epilogue at
  `0x8013619C..0x801361A8` restores them and returns.
- There are exactly two retained direct calls: `0x80142388`, in
  `SubmitSceneSectionFaces`, and `0x80172DEC`, in
  `PrepareVisibleQuadTransform`.
- Both callers pass the word at owner/transform offset `+0x44` as `a0`.
- No internal address is directly called. The dispatch rows at `0x80136098`,
  `0x801360A8`, `0x801360C0`, `0x80136190`, and `0x8013619C` are resumable
  control-flow continuations.
- The callers ignore `v0`, and the routine establishes no semantic result.

The defensible logical signature is therefore:

```c
void InstallLinkedRenderTransform(LinkedTransform *transform); // a0, non-null
```

`a1` through `a3` are not inputs. The source-level type name is provisional;
the `+0x44` link and transform layout are instruction-level facts.

## Exact behavior

The routine first loads `0x801E14F0` and calls `0x8015F6A4`. That library leaf
writes its argument to GTE control register 26 (`H`), so this establishes the
current projection-plane distance.

It then repeatedly replaces the current pointer with `current->field_44` while
that word is nonzero. The matrix data always comes from the final non-null
record. In particular, there is no matrix multiplication or accumulation in
the loop, so calling this a composed or hierarchical transform would overstate
the evidence.

At scratchpad address `0x1F800010`, it constructs the standard 32-byte PSYQ
`MATRIX` layout. Let `T` be the terminal record, `S = *(s32 *)0x801E14EC`, and
`C = *(s32 *)0x801E14F4`. The stores are equivalent to:

```c
MATRIX *m = (MATRIX *)0x1F800010;

m->m[0][0] = *(u16 *)(T + 0x00);
m->m[0][1] = *(u16 *)(T + 0x02);
m->m[0][2] = *(u16 *)(T + 0x04);

m->m[1][0] = (s16)((*(s16 *)(T + 0x06) * S) >> 8);
m->m[1][1] = (s16)((*(s16 *)(T + 0x08) * S) >> 8);
m->m[1][2] = (s16)((*(s16 *)(T + 0x0A) * S) >> 8);

m->m[2][0] = *(u16 *)(T + 0x0C);
m->m[2][1] = *(u16 *)(T + 0x0E);
m->m[2][2] = *(u16 *)(T + 0x10);

m->t[0] = 0;
m->t[1] = 0;
m->t[2] = C >> 1;
```

The halfword casts above represent the exact low-halfword stores. The middle
row inputs are sign-extended before multiplication and the products are
arithmetically shifted right by eight. The other six rotation elements are
copied without arithmetic.

Finally it calls `0x8015F644(m)` and `0x8015F664(m)`. Those leaves install
`m->t[0..2]` into GTE `TRX/TRY/TRZ` and the five packed rotation words into GTE
control registers 0 through 4, respectively. Thus the observable output is
GTE `H`, translation, and rotation state plus the scratch matrix itself.

## Coefficient relationship

`RebuildViewportClipCoefficients` (`0x8013535C`) and its scalar-input sibling
at `0x80135B8C` produce all three globals consumed here:

- `0x801E14F0`: written directly to GTE `H`;
- `0x801E14EC`: fixed-point scale applied only to matrix row 1;
- `0x801E14F4`: halved into the Z translation component.

This producer relationship establishes that the matrix adaptation is tied to
the current viewport/projection setup. It does not, by itself, justify more
specific world/view/camera field names for the terminal record.

## Confidence and limits

- **High:** exact boundary, two call sites, one pointer argument, `+0x44` chain
  traversal, terminal-record selection, all scratch stores, fixed-point math,
  and exact GTE control registers installed.
- **High:** the chain is followed but not composed.
- **Medium:** `LinkedTransform` and “render transform” as source-level terms.
- **Unresolved:** the producer of the linked records, ownership semantics of
  the chain, and the original function/type names.
